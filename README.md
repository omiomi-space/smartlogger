# SmartLogger

スマホの IMU（姿勢・加速度・ジャイロ・地磁気）、気圧、GPS を UDP でリアルタイム送信する Android アプリと、
PC 側で受信してスマホの位置・姿勢・動きを 3D モデルで表示するビューアです。

```
[Android: SmartLogger]  --UDP/JSON (既定 50Hz, port 5005)-->  [PC: pc_viewer/viewer.py (Panda3D)]
```

## 構成

| パス | 内容 |
|---|---|
| `release/SmartLogger.apk` | ビルド済み APK（そのままインストール可能） |
| `android/` | Android アプリのソース（Java、外部ライブラリなし） |
| `pc_viewer/viewer.py` | 3D リアルタイムビューア |
| `pc_viewer/fusion.py` | 位置推定フィルタ（加速度デッドレコニング + GPS + 気圧 + 静止検出） |
| `pc_viewer/simulate_sender.py` | 疑似スマホ送信 / 記録データの再送信 |
| `pc_viewer/eval_fusion.py` | シミュレーションの真値に対するフィルタ精度の評価 |

## 使い方

### 1. スマホ側

1. `release/SmartLogger.apk` をスマホにインストール（`adb install release/SmartLogger.apk` か、ファイルを転送して開く）。
2. アプリを起動し、位置情報の権限を許可。
3. **PC IP address** に PC の IP アドレス（例 `192.168.1.10`）を入力。`255.255.255.255` のままなら同じ LAN 内にブロードキャストします。
4. ポート（既定 5005）と送信レート（既定 50Hz）を確認して **START**。
5. **Use camera for position (ARCore VIO)** がオン（既定）なら、カメラ権限を許可すると背面カメラで位置を追跡します。
   カメラ映像は送信も保存もせず、ARCore が計算した位置と姿勢だけを送ります。ARCore 非対応の端末ではカメラなしで動きます。

スマホと PC は同じネットワーク（Wi-Fi / テザリング）に接続してください。送信中は画面が消えないようになっています（アプリをバックグラウンドにすると送信が止まる端末があります）。

### 2. PC 側

```powershell
pip install -r pc_viewer/requirements.txt
```

```powershell
python pc_viewer/viewer.py
```

起動時に Windows ファイアウォールの受信許可ルール（`SmartLogger-UDP-<ポート>`）があるか確認し、無ければ
「UDP ポート 5005 の受信を許可しますか？」というダイアログを表示します。「はい」→ 管理者権限の確認 (UAC) を許可すると、
全ネットワークプロファイル（プライベート/パブリック/ドメイン）でそのポートの UDP 受信を許可するルールを追加します。
2 回目以降はルールがあるので表示されません。確認を出したくない場合は `--no-firewall` を付けて起動してください。

ルールを削除する場合（管理者 PowerShell）:

```powershell
netsh advfirewall firewall delete rule name=SmartLogger-UDP-5005
```

#### データが届かないとき（ESET などのセキュリティソフト）

ESET などのファイアウォールが入っている PC では、Windows ファイアウォールのルールが使われず、スマホから突然届く UDP が捨てられることがあります。
そのためビューアは、PC から 1 秒ごとにスマホへ「呼びかけ」パケット（`SMARTLOGGER_HELLO`）を送り、アプリはその送り元へデータを返します。
PC から始めた通信への返信になるので、受信を止めるファイアウォールでも通ります（アプリ画面に `sending to: ... (PC hello)` と表示されます）。
呼びかけが 5 秒途切れると、アプリは **PC IP address** の宛先へ送る通常の動作に戻ります。

**スマホの IP は自動で探します（既定 `--phone auto`、ADB 不要）。** データが 3 秒届かない間、2 秒ごとに次の宛先へ呼びかけ、
最初に返事をくれた端末に固定します（画面左上に `searching 192.168.x.0/24 ...` と表示）。

1. PC がつながっている各ネットワークのブロードキャスト（例 `192.168.128.255`）
2. ARP テーブルにある近くの端末
3. 3 回に 1 回はネットワーク内の全アドレス（/22 以下のネットワークのみ。/24 なら 254 個の小さな UDP）

VirtualBox・Hyper-V・WSL・VPN・Tailscale などの仮想アダプタは対象外です。
探索を使わない場合は IP を直接指定（`--phone 192.168.128.187`、スマホのアプリ画面の `this phone:` に表示）、
ADB 接続中なら `--phone adb`、呼びかけ自体を止めるなら `--phone none` です。

同じポートで 2 つ目のビューアを起動するとエラーで止まります（Windows では 2 つのプログラムが同じポートを共有でき、データが分かれてしまうため）。

オプション:

| オプション | 既定 | 説明 |
|---|---|---|
| `--port` | 5005 | 受信 UDP ポート |
| `--scale` | 8 | スマホモデルの表示倍率（実寸比） |
| `--alt` | baro | 高さのソース（`baro` 気圧 / `gps`） |
| `--mode` | ekf | 位置の推定方法（`ekf` 加速度 + GPS の融合 / `gps` GPS のみ） |
| `--smooth` | 4 | GPS のみモードの位置平滑化レート [1/s] |
| `--accel-scale` | 0.3 | 加速度矢印の長さ [m per m/s²] |
| `--no-firewall` | - | 起動時のファイアウォール確認をしない |
| `--phone` | auto | スマホの探し方: `auto` ネットワーク探索 / `adb` / `none` / `IP[:ポート]` 直接指定 |
| `--phone-port` | `--port` と同じ | アプリ側の UDP ポートが PC の受信ポートと違うとき |
| `--record` | - | 受信したパケットを JSONL ファイルに追記保存する |

操作: 左ドラッグ = 視点回転 / ホイール = ズーム / `F` = 追従 ON/OFF / `R` = 原点リセット / `T` = 軌跡表示 / `A` = 加速度矢印 / `K` = EKF ⇔ GPS のみ 切替 / `G` = GPS 生値マーカー表示 / `Esc` = 終了

スマホなしで動作確認（楕円コースを歩いて止まる、を繰り返す疑似データ）:

```powershell
python pc_viewer/simulate_sender.py
```

記録したデータを再生してビューアで見る:

```powershell
python pc_viewer/viewer.py --phone 192.168.128.187 --record walk.jsonl
```

```powershell
python pc_viewer/simulate_sender.py --replay walk.jsonl
```

### 表示内容

- **姿勢**: Android の Rotation Vector センサー（なければ Game Rotation Vector）のクォータニオン
- **位置**: [`fusion.py`](pc_viewer/fusion.py) のカルマンフィルタで推定（下記）。原点は計測開始地点、東(E)/北(N)/上(U) [m]
- **水色の ×**: GPS の生の測位点（`G` で表示切替）。フィルタ出力とのずれを見比べられます
- **紫の矢印**: 線形加速度（重力除去済み）をワールド座標に変換したもの
- **オレンジの線**: 移動軌跡
- 画面左上: 速度・静止判定 (`STILL`/`moving`)・最後の GPS からの経過時間・位置の推定誤差 (σ)・加速度バイアス推定値
- 座標系: X = 東（赤）, Y = 北（緑）, Z = 上（青）。スマホ上の軸は端末座標（X 右, Y 画面上方向, Z 画面手前）

### 位置推定（EKF / デッドレコニング）

GPS はスマホでは 1 秒に 1 回程度しか更新されず誤差も数 m（屋内では数十 m で位置がほぼ固まる）あるため、
GPS の間を加速度と歩行者デッドレコニング (PDR) で埋めます。
状態は 位置(3) + 速度(3) + 加速度バイアス(3) の 9 次元カルマンフィルタです。

手持ちのスマホは歩くと ±2〜3 m/s² 揺れるので、加速度の 2 回積分だけでは数秒で破綻します。
歩行中は「1 歩ごとの歩幅 ÷ 周期」をスマホの向いている方向の速度として与える PDR が位置を運びます。

| 処理 | タイミング | 内容 |
|---|---|---|
| 予測 | 毎パケット (50Hz) | 線形加速度を姿勢クォータニオンでワールド座標に回し、バイアスを引いて積分 |
| GPS 位置 | 新しい測位ごと | 端末が報告する精度を σ に使用。外れ値は信頼度を自動で下げる |
| GPS 速度 | 新しい測位ごと | 速度 + 進行方位から東/北の速度（精度 10 m より悪いとき＝屋内では使わない） |
| 歩行 (PDR) | 1 歩ごと | 鉛直加速度のピークで歩数を検出、歩幅は揺れの大きさから推定 (Weinberg, 0.3〜1.1 m)、方向はスマホの向き（画面上方向 + 背面方向の水平成分） |
| カメラ VIO (ARCore) | 30fps | 基準点からの ARCore の移動量を位置として 3 軸で入力（基準点は 2 秒ごと・ARCore の跳び・追跡切れで取り直し）。Wi-Fi が途切れても移動量は失わない。追跡中は PDR より優先 |
| 立ち止まり | 1.2 秒歩数なし | 水平速度 = 0（手持ちで完全には静止しなくても止まっていると扱う） |
| 気圧高度 | 10Hz | 最初の気圧からの相対高度 |
| 静止検出 (ZUPT) | 毎パケット | ジャイロと加速度が 0.4 秒静かなら速度 = 0 とし、GPS のふらつきに引っ張られにくくする |
| 速度の減衰 | GPS が途切れたとき | PDR を切った場合のみ。GPS 間隔の 2.5 倍以上来ないときは速度を弱く 0 に寄せる |

GPS で位置が補正されたときは、表示上は 0.5 秒かけて滑らかに寄せます。

シミュレーション（真値あり）での水平位置誤差 RMS（`python pc_viewer/eval_fusion.py`）:

| GPS 間隔 | GPS のみ | EKF（加速度 + PDR） | EKF + カメラ (`--ar`) |
|---|---|---|---|
| 1 秒 | 3.6〜4.0 m | 2.2 m | 0.3 m |
| 4 秒 (`--gps-rate 0.25`) | 4.3〜4.8 m | 2.8 m | 0.4 m |

（シミュレータの ARCore には再ローカライズの跳びが無いので、カメラありの数字は楽観的です）

ARCore 座標の水平の向きは、スマホの姿勢から自動で合わせます。地磁気は屋内で ±40° 以上乱れるため、
アプリが送る地磁気なしの姿勢（ゲーム用回転ベクトル `qg`）との差で ARCore を合わせ（ARCore の跳びにもすぐ追従）、
北の向きだけを地磁気から約 60 秒かけてゆっくり合わせます。`qg` の無い古い記録では、地磁気を約 70 秒で平均して使います。

実機:
- 屋内の廊下（約 50 m）を往復し、行きと帰りに途中のホールで四角形を歩行（4 分、GPS 精度 中央値 39 m、Wi-Fi で
  パケットの 30% が欠け最長 41 秒途切れ、ARCore の跳び 2 回）: カメラありでは行き帰りと 2 つの四角形がほぼ重なり、
  終点と始点のずれ 6.3 m。歩数のみ（PDR）では四角形の形が崩れ、ずれ 13.7 m。
- 机に置いて 40 秒（GPS 精度 6 m）: 推定位置の移動量の合計 0.26 m
- 屋内を 96 秒歩行（GPS は精度 10〜120 m でほぼ動かず、速度は常に 0 と報告）: 133 歩、歩幅 平均 0.64 m、
  歩行速度 約 1.0 m/s で軌跡が出る（GPS だけでは 3 m 四方から動かない）

画面左上には歩数・歩幅・状態（`WALKING` / `standing` / `STILL`）も表示します。
歩幅が合わないときは `FusionParams.step_k` を調整してください（大きくすると歩幅が伸びます）。
パラメータは `fusion.py` の `FusionParams` にまとまっています。

## UDP パケット形式

1 パケット = UTF-8 の JSON 1 オブジェクト。値が取得できていない項目は省略されます。

```json
{
  "v": 1, "seq": 1234, "t": 1764230000000,
  "q":   [w, x, y, z],
  "qg":  [w, x, y, z],
  "acc": [x, y, z],
  "gyr": [x, y, z],
  "mag": [x, y, z],
  "lin": [x, y, z],
  "p":   1013.25,
  "gps": {"lat": 35.0, "lon": 139.0, "alt": 40.0, "acc": 3.0, "spd": 1.2, "brg": 90.0, "prov": "gps", "t": 1764230000000},
  "ar":  {"st": "TRACKING", "n": 1234, "ts": 605960049.6, "p": [x, y, z], "q": [w, x, y, z]}
}
```

| キー | 単位 | 説明 |
|---|---|---|
| `seq` | - | 連番（パケットロス検出用） |
| `t` | ms | 送信時刻（Unix epoch） |
| `q` | - | 端末座標 → ワールド座標(ENU) の回転クォータニオン |
| `qg` | - | 同じく地磁気を使わない版（ゲーム用回転ベクトル。水平の向きは任意だが屋内でも安定） |
| `acc` | m/s² | 加速度（重力込み、端末座標） |
| `gyr` | rad/s | 角速度（端末座標） |
| `mag` | µT | 地磁気（端末座標） |
| `lin` | m/s² | 線形加速度（重力除去、端末座標） |
| `p` | hPa | 気圧 |
| `gps.alt` | m | 楕円体高 |
| `gps.acc` | m | 水平精度 |
| `gps.spd` / `gps.brg` | m/s / deg | 速度 / 進行方位 |
| `ar.st` | - | ARCore の追跡状態（`TRACKING` / `PAUSED` / `STOPPED`）。追跡できない理由は `ar.why` |
| `ar.n` / `ar.ts` | - / ms | カメラフレーム番号 / フレーム時刻（端末の単調時計） |
| `ar.p` / `ar.q` | m / - | 端末（センサー座標）の位置と姿勢。ARCore のワールド座標（Y が上、水平の向きは任意） |

## ビルド

Android Studio の JDK と Android SDK (API 36) が必要です。

```powershell
cd android; .\gradlew assembleRelease
```

出力: `android/app/build/outputs/apk/release/app-release.apk`（サイドロード用にデバッグ鍵で署名）。
